# 片段取材 · 浏览器助手 0.1.1

这是原有“片段取材”工具的浏览器辅助组件，供桌面版 Chrome、Edge 使用。它利用用户已经登录的迅雷、百度网页，观察网页正常产生的文件入口，并发送给本机原工具的“浏览器直连”路径。下载、时间选择、队列和保存仍在原工具中完成。现阶段是开发验收版本，尚未上架扩展商店，也没有完成真实网盘兼容验收。

## 本次范围

- 仅支持 `https://pan.xunlei.com/` 和 `https://pan.baidu.com/` 页面；不包含 Safari、其他网盘或手机浏览器。
- 不建立独立账号系统，不在工具中要求再次登录，不访问浏览器磁盘配置。
- 不读取 Cookie、密码或 Authorization，不自动播放视频、不自动启动网页下载。
- 迅雷页面可列出当前官方网页已加载的普通空间视频。用户明确选择影片并点击“读取所选文件入口”后，助手调用当前官方页面已有的 `drive/getFileInfo` 动作，固定使用 `DISPLAY`；授权和请求校验交给官方页面处理。助手不自行生成签名、不直接发网盘 API 请求，也不导出官方会话凭据。
- 迅雷入口只接受本次新详情响应中的 `web_content_link`，核对文件 id、名称和大小。不从官方 store 可能保留的旧 URL 回退，不尝试 `PLAY`、`CONSUME`、`FETCH`；未返回原文件时明确失败。单次读取有 20 秒上限，停止识别和文件变化会丢弃晚到结果。
- 观察当前顶层网页的 Fetch/XHR JSON 响应、明确文件链接和资源地址，优先识别 `web_content_link`、`dlink` 等原文件候选字段。`blob:`、HLS、DASH、常见预览流和账号 API 地址不作为文件入口发送。
- 捕获结果只是候选。是否原文件、是否支持区间读取、是否可在本机使用，由原工具进一步核验。抓到地址不代表开始下载，更不代表已验证提速。

## 安装测试版

当前没有扩展商店安装链接，需要开发模式加载一次：

1. 完整解压本目录，保留所有文件。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
3. 启用“开发者模式”，选择“加载已解压的扩展程序”，选中本目录。
4. 将“片段取材 · 浏览器助手”固定到浏览器工具栏，便于之后点击。

这是当前开发测试方式，不能作为“正式安装包已实现一键安装”的验收结论。正式分发仍需完成浏览器商店或受支持的分发流程。

## 配对与使用

1. 打开原有片段取材，在“浏览器直连”中点击“在 Chrome / Edge 连接助手”。
2. 在打开的本机帮助页中点击助手显示的“连接当前工具”。只响应真实点击，不自动配对。如未显示按钮，请先加载此扩展并刷新本页。手工复制原工具配对地址并在助手弹窗中粘贴连接，仍可作为兜底；地址仅指向本机 `127.0.0.1`，不要发给其他人。
3. 在 Chrome 或 Edge 中正常登录迅雷或百度网盘，打开影片所在页面。
4. 点击助手的“开始识别当前网页”。迅雷页面可刷新助手中的影片列表、选中影片，再点“读取所选文件入口”，无需播放；百度当前仅观察网页正常文件操作，不包含主动详情动作。
5. 有候选时，助手显示发送数量；回到原工具检查候选、填写片段时间，并使用原有任务队列下载。
6. “停止识别”可随时停止当前页面的捕获；它不会取消原工具里已经创建的下载任务。网页刷新或切换后需重新开始识别。

原工具重启或重新生成配对信息后，旧地址可能失效，重新点击原工具的浏览器连接按钮即可配对。配对只保存在 `chrome.storage.session` 内存会话中，跨扩展后台休眠保留，浏览器退出后清除；不使用 `storage.local` 保存配对令牌，没有持久化兜底。缺少临时存储能力时明确提示更新浏览器。相同配对不打断识别；用户确认连接另一工具后，旧连接的网页识别停止，已经创建的下载任务不受影响。

## 明确限制

- 百度当前只能观察网页实际产生的请求；迅雷新增的显式详情动作依赖当前官方页面内部动作，网站更新可能使其失效。动作失败、没有原文件地址或文件状态不一致时，不改用播放流，不要求播放来触发请求，保留旧路径。
- 开始识别以前已经完成的 JSON 请求不能事后完整读取；现有可见资源地址会尝试识别，但不保证可用。
- 顶层页面之外的 iframe、Web Worker 请求，以及页面提前保存的私有网络函数，可能无法观察。没有新的可核对详情响应时，迅雷显式动作也会失败，不能用 store 中旧地址冒充成功。当前不添加全站权限或读取完整浏览器流量。
- 某些地址需要额外 Cookie、Authorization 或特定请求头，此版只附带当前浏览器 User-Agent 与去掉查询参数的网页 Referer，可能无法在桌面工具中使用。
- 当前两个网盘共用捕获与回传框架，不等于百度和迅雷原文件取片已真实验证；账号权限、资源状态、链接过期和速度仍需分别验收。
- 配对信息和安全文件列表仅在浏览器临时会话中使用；捕获的签名链接只在传输所需内存中使用，不保存到扩展持久存储。不向远端服务上传候选。

```sh
node --test browser-helper/test/*.test.mjs
```

这些测试验证过滤、配对、消息边界、回传和取消行为；使用本机合成数据，不作为真实 Chrome/Edge 网盘兼容或提速结论。
